# Reproducing the FTW label-validity study (6 regions)

This documents the exact pipeline behind `docs/FTW_LABEL_VALIDITY_RESULTS.md`. Large binaries
(`data/chips_ftw_*`, `data/features_per_pixel_ftw_*`) are **not** in git (see `.gitignore`); they are
regenerated by the steps below or obtained from the hosted data bundle (see "Data hosting").
All result JSONs under `data/results/` **are** committed and checksummed (`scripts/checksums.py --verify`).

## Environment
- Main venv: `./.venv` (pyarrow 24.0.0). FTW download CLI: `./.venv-ftw` (gitignored).
- GEE auth required for the S2/WorldCover pulls (`ee.Initialize()`).

## Per-country pipeline (india, kenya, vietnam, france, netherlands)

```bash
C=vietnam          # one of: india cambodia kenya vietnam france netherlands
PY=./.venv/bin/python

# 1. FTW true labels (download is UA-gated at source.coop → browser-UA curl)
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120 Safari/537.36"
curl -s -A "$UA" -o /tmp/ftw_${C}_dl/${C}.zip \
  "https://data.source.coop/kerner-lab/fields-of-the-world-archive/${C}.zip"
unzip -q -o /tmp/ftw_${C}_dl/${C}.zip -x 's2_images/*' -d /tmp/ftw_${C}_dl
cp /tmp/ftw_${C}_dl/chips_${C}.parquet data/ftw/ && cp /tmp/ftw_${C}_dl/data_config_${C}.json data/ftw/
$PY scripts/ftw_to_polygons.py --country $C --ftw-dir /tmp/ftw_${C}_dl \
    --out data/labels/polygons_ftw_${C}.parquet

# 2. Index: least-cloud S2 scene per FTW chip centroid in the FTW window_a
#    (window read from data_config; see WINDOWS dict in build_ftw_index.py)
$PY scripts/build_ftw_index.py --country $C --limit 800 --out data/index/ftw_${C}.jsonl

# 3. Full pipeline: pull S2+WorldCover -> manifest -> rekey polygons to chip_ids
#    -> extract 4 FMs (TRUE + PROXY) -> controlled + standalone + bootstrap
bash run_ftw_country.sh $C          # (driver; no `set -e` so transient GEE 503s don't abort)

# 4. Scene-disjoint robustness (group split by MGRS tile instead of chip)
$PY scripts/ftw_controlled_label_comparison.py --country $C --group-by tile
```

## Key design points (answers to common audit questions)
- **Same-pixel paired true-vs-proxy:** `ftw_controlled_label_comparison.py` samples ONE pixel set per
  chip and scores it under BOTH labels (FTW field-membership vs WorldCover-cropland). One shared pixel
  table, identical chip-grouped split, identical valid-mask. `n_pixels` in each `*_controlled_*.json`
  is the single shared count (e.g. India 213611), `chip_overlap=0`.
- **FM↔RF parity:** `eval_per_pixel.py` and `eval_nonfm_baseline_per_pixel.py` both split-then-mask on
  the identical strata-kept set + seed, so the spectral RF and the FM probes see byte-identical chip
  partitions (the controlled comparison enforces this directly).
- **Imagery alignment:** FTW polygons (absolute lat/lon) are rasterised onto OUR pulled-S2 chip grid via
  the chip transform, so labels and features are co-registered by construction; the high true-label
  AUROCs (0.94–0.98 for strong FMs) are themselves evidence of correct alignment.
- **CRS/area:** polygon areas computed in the local UTM after transforming to EPSG:4326 first
  (`ftw_to_polygons.py`, `ftw_field_sizes.py`).

## Artifacts (all checksummed)
- `data/results/ftw_controlled_label_comparison{,_<country>}.json` — same-pixel true-vs-proxy (headline)
- `data/results/ftw_controlled_label_comparison{,_<country>}_tilesplit.json` — scene-disjoint robustness
- `data/results/ftw_bootstrap_ci_<country>.json` — chip-clustered bootstrap 95% CIs + paired deltas
- `data/results/eval_per_pixel_ftw_<country>_{true,proxy}{,_anysat,_nonfm_rf}_chip.json` — standalone evals
- `data/results/ftw_edge_zone_eval_india.json` — edge-pixel interior-vs-boundary control
- `data/results/ftw_proxy_mismatch_coverage.json` — true-field coverage vs WC-cropland fraction per region
- Verify: `python scripts/checksums.py --verify`
